# Faster MCP bridge and facing-side arrows

- [DIFFICULTY] A divergence run on the vision board took 11 tool calls. Every write tool echoed the whole board, about 60K characters, which overflowed the client's output limit and needed extra parse calls just to find new IDs.
- [NUMBER] Real board at revision 170: 95 elements, but only 28 were live and meaningful. `read_board` went from 62,794 to 6,688 characters after compaction.
- [DECISION] `read_board` drops deleted elements and render-only fields and folds bound labels into their shapes. Writes return `{revision, ids}`. `add_elements` takes `connections` (item index or existing id), so nodes and arrows land in one call.
- [DECISION] `connectElements` leaves from the side facing its target. The old right-edge → left-edge rule made arrows between stacked boxes loop back across the board.
- [LEARNED] The running MCP process keeps the old code until the client restarts it. The board rebuild ran as one direct patch to the workspace API, under a second, against 20+ slow tool calls.
- [LEARNED] The user wants numbered options in chat to pick from before anything is written to the board.
- [VERIFICATION] Local suite 16/16, including a new test for batch connections, compact reads and small acks. The rebuilt board was checked in the browser.
